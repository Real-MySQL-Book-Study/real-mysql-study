# Q7. 세미 조인 최적화 (영섭 현서)

### 1. 세미 조인(Semi Join)이란?
다른 테이블과 실제 조인하여 데이터를 가져오는 것이 아니라, **다른 테이블에 조건에 일치하는 레코드가 "있는지 없는지"만 확인**하는 형태의 쿼리입니다. 주로 서브쿼리(`IN`, `EXISTS`) 형태로 작성됩니다.

### 2. 과거의 문제점 (MySQL 5.5 이하)
과거에는 세미 조인 최적화 기능이 부족하여 아래와 같은 쿼리를 실행할 때 비효율이 발생했습니다.

```sql
SELECT * FROM employees e
WHERE e.emp_no IN 
    (SELECT de.emp_no FROM dept_emp de WHERE de.from_date = '1995-01-01');
```

* **동작 방식:** 외부 테이블(Outer Table)을 **풀 테이블 스캔(Full Table Scan)** 하면서, 레코드 **한 건마다** 서브쿼리를 반복해서 실행하여 조건 일치 여부를 확인했습니다.
* **결과:** 이를 **DEPENDENT SUBQUERY** 패턴이라고 하며, 외부 테이블의 데이터 양이 많을수록 쿼리 성능이 급격히 저하되는 문제가 있었습니다.

---

### 3. 세미 조인 최적화 전략 (MySQL 5.6, 8.0 이상)
최신 MySQL 옵티마이저는 이러한 쿼리를 인식하여, 내부적으로 **조인(Join)과 유사하게 처리하거나 더 효율적인 방식**으로 실행 계획을 재작성합니다. 대표적인 5가지 전략은 다음과 같습니다.

#### ① Table Pull-out (테이블 풀아웃)
* **설명:** 서브쿼리를 외부 쿼리로 끄집어내어 **일반적인 `INNER JOIN` 형태로 쿼리를 재작성**하는 방식입니다.
* **특징:** 서브쿼리의 결과가 중복되지 않음이 보장될 때(예: PK나 유니크 키 조회) 사용되며, 가장 효율적인 방식 중 하나입니다.

#### ② First Match (퍼스트 매치)
* **설명:** `IN (subquery)` 형태를 `EXISTS (subquery)`와 유사하게 처리합니다.
* **동작:** 외부 테이블의 레코드에 대해 내부 테이블을 검색하다가, **첫 번째로 일치하는 레코드를 발견하면 즉시 검색을 멈추고** 다음 외부 레코드로 넘어갑니다(Short-circuit).

#### ③ LooseScan (루스 스캔)
* **설명:** 서브쿼리 테이블의 인덱스를 읽을 때, 중복된 값은 건너뛰고 **그룹당 하나의 레코드만 읽는 방식**입니다.
* **특징:** `GROUP BY` 최적화와 유사하며, 서브쿼리 테이블이 크더라도 인덱스를 통해 효율적으로 처리합니다.

#### ④ Materialization (구체화)
* **설명:** 서브쿼리의 결과를 **임시 테이블(Temporary Table)**로 생성(구체화)해 두고, 외부 테이블과 조인하는 방식입니다.
* **특징:** 인덱스를 활용해 빠르게 조인하며, 서브쿼리 결과 크기에 따라 메모리나 디스크를 사용합니다.

#### ⑤ Duplicate Weedout (중복 제거)
* **설명:** 세미 조인을 일반적인 `INNER JOIN`처럼 실행하되, 마지막에 **중복된 레코드를 제거**하는 방식입니다.
* **특징:** `GROUP BY`나 임시 테이블을 사용하여 중복을 걸러냅니다.
